# 관리 접속 제한 (ACL)

장비 관리 접속(SSH, ping)을 관리망으로 제한하는 설계

샘플: [10-mgmt-acl.md](../../samples/dc1/10-mgmt-acl.md)

## 설계값

| 항목 | 값 |
|---|---|
| ACL 이름 | `MGMT-ACL` |
| 방식 | control-plane ACL (`system control-plane`에 `in`으로 적용) |
| 허용 출발 주소 | 관리망 `192.168.100.0/24` (SSH, ICMP) |
| 같이 허용 | OSPF, BGP(`10.1.0.0/24` 루프백끼리), MLAG 피어(`10.1.254.0/24`), 장비 간 ICMP(`10.0.0.0/8`) |
| 차단 | 그 밖의 모든 IP (`deny ip any any log`) |

## 규칙

| 순서 | 동작 | 대상 | 용도 |
|---|---|---|---|
| 10 | permit | tcp `192.168.100.0/24` -> SSH(22) | 관리망 SSH |
| 20 | permit | icmp `192.168.100.0/24` | 관리망 ping |
| 30 | permit | ospf any any | 언더레이 이웃 |
| 40 | permit | tcp `10.1.0.0/24` -> BGP(179) | EVPN 이웃(요청) |
| 50 | permit | tcp `10.1.0.0/24` 출발 BGP(179) | EVPN 이웃(응답) |
| 60 | permit | ip `10.1.254.0/24` | MLAG 피어 통신 |
| 70 | permit | icmp `10.0.0.0/8` | 장비 간 ping 확인 |
| 80 | deny | ip any any (log) | 나머지 차단 |

## 적용 장비

| 장비 | 관리 IP | 적용 방식 | 상태 (2026-10-22) |
|---|---|---|---|
| leaf1 | 192.168.100.21 | control-plane ACL `MGMT-ACL` | **장비 적용과 검증 완료** |
| leaf2 | 192.168.100.22 | 같음 | 장비 적용과 검증 완료 |
| leaf3 | 192.168.100.23 | 같음 | 장비 적용과 검증 완료 |
| leaf4 | 192.168.100.24 | 같음 | 장비 적용과 검증 완료 |
| spine1 | 192.168.100.11 | 같음 | 장비 적용과 검증 완료 |
| spine2 | 192.168.100.12 | 같음 | 장비 적용과 검증 완료 |
| DSW1, DSW2, ASW1 (Cisco IOSv) | 192.168.100.44 ~ .46 | vty `access-class`로 제한할 예정 | 미작성 |
| CX1, CX2, CX3 (Aruba) | 192.168.100.41 ~ .43 | mgmt 인터페이스 ACL로 제한할 예정 | 미작성 |
| PE1~PE3, Hub1, Hub2, BGW1, BGW2 (c7200) | 없음 | 관리망에 연결하지 않고 콘솔로만 접속 | 해당 없음 |
| MGMT-SW (vEOS) | 없음 | `Management1` 미사용, 기본 L2 스위치 | 해당 없음 |

## 알려진 동작

- 설정이 없는 vEOS(ZTP 중인 장비)가 보내는 DHCP 요청이 규칙 80에 걸려 로그에 남음. 영향은 없음
- 규칙 80 앞에 허용을 추가하는 경우 순서 번호를 10 단위로 띄워 두면 중간에 끼워 넣기 쉬움
- 다른 장비에서 이 장비로 SSH를 하려면 출발 주소가 관리망이어야 함. 예를 들어 spine1의 링크 주소(`10.1.10.0`)에서 leaf1로 가는 SSH는 차단됨
